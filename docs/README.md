# Studio 仓库文档地图

这是人和 AI 共用的**全仓查找入口**，负责指路，不复制规则正文或替代实时状态。仅使用工作台时直接读[制作人指南](../app/docs/USER_GUIDE.md)，不必读完仓库。

## 按问题找信息

| 我想知道什么 | 先读哪里 | 还需要核对什么 |
|---|---|---|
| 想学习开发历程、批准框及新连接器设置 | [开发资料与设置入口](development-history/README.md) | 已实施、已验证、待验收不同；新验证规则不替换旧 Studio |
| 工作台怎么用、怎么交接设计 | [制作人指南](../app/docs/USER_GUIDE.md) | 按指南完成外部设计讨论、确认文档、指定负责人和处理范围 |
| 让 AI 代我操作 | [代理制作人说明](../app/docs/PRODUCER_PROXY_GUIDE.md) | 本次委托允许发送、跟进还是验收；不是默认无限授权 |
| 产品要做什么、不做什么 | [PRD](../PRD.md) | 已确认要求；不能由暂未实现推断需求取消 |
| 现在做到哪里、还有哪些问题 | [状态与证据入口](STATUS.md) | 日期和适用版本；正在运行的任务须另查实际工作台 |
| 为什么这样实现、代码在哪里 | [架构](../ARCHITECTURE.md) → [代码与数据地图](CODE_MAP.md) | 对应源码、测试和实际配置 |
| 下一步做什么 | [当前工作与规划](../IMPLEMENTATION_PLAN.md) | 待改进不等于已经授权执行 |
| 主策划、主开发、DSH 的规则在哪里改 | [规则总入口](../rules/README.md) | 基础角色、补充要求、工具协议和程序约束是不同层 |
| 工具怎么调用、怎么委派和回传 | [AI 操作协议](../app/docs/AI_OPERATOR_GUIDE.md) | 当前工具 schema；不复制旧 JSON 当永久接口 |
| 启动、配置、认证、备份和故障恢复 | [运行手册](../app/docs/RUNBOOK.md) | 当前工程身份、活动执行及未知投递；不要照旧报告重放命令 |
| 查某次失败、修复或验收的依据 | [历史证据目录](EVIDENCE.md) | 原报告日期、测试类型、原始回执；旧通过不等于当前通过 |
| 一个文件到底是什么、该不该改 | [文件职责清单](CATALOG.md) | 文件用途、当前/历史性质及更新责任 |
| 新文档放哪里、发现矛盾怎么办 | [文档维护约定](MAINTENANCE.md) | 按职责核对，不能只挑日期最新的一份 |

## 仓库结构

```text
RRPG_AI_Studio/
  README.md                 人工起点、产品简介和启动入口
  AGENTS.md                 AI 接手导航与操作边界
  PRD.md                    已确认产品要求
  ARCHITECTURE.md            技术职责与边界
  IMPLEMENTATION_PLAN.md     当前工作入口、待办和适用范围
  docs/                     全仓地图、文件职责、状态、维护规则
  rules/                    程序实际读取的角色/补充，以及 Skill/Harness 导航
  app/
    docs/                   使用、操作、维护手册；旧报告按证据目录辨认
    src/                    实现
    tests/                  自动化与隔离浏览器回归
    scripts/                启动、备份、诊断等工具
    runtime/                私有运行数据（不是文档，默认不检索）
    workspaces/             执行工作目录（不是已验收源码）
  reports/                  本机阶段报告与证据（默认不入 Git）
  archive/                  私有历史归档（默认不检索、不运行）
```

这是 Studio 自身的知识结构。游戏设计、游戏规则及游戏源码仍在获授权的游戏工程，不复制成 Studio 的第二套游戏权威。

## 最短阅读路线

- **制作人**：根 README → 制作人指南 → 按实际问题查本地图。
- **代理制作人**：根 AGENTS → 代理说明 → 对应操作章节。
- **维护开发 AI**：根 AGENTS → 本地图 → 状态 → 对应需求/架构 → 源码与测试。只读所需专题，不整包吞入历史。
- **追查故障**：当前失败记录 → 对应模块 → 同类历史证据。先确认是否仍是同一个原因，再采取行动。

本地图不会自动加载到 Studio 两位负责人的模型上下文；实际注入机制见[规则说明](../rules/README.md)。
