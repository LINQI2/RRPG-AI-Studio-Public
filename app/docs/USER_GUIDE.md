# 制作人使用指南

适用版本：2026-10-22 当前源码。先读本页即可开始日常使用；配置由维护者按[运行手册](RUNBOOK.md)处理。接手的 AI 阅读[AI 操作协议](AI_OPERATOR_GUIDE.md)。完整文档入口见[帮助目录](INDEX.md)。

## 已确认的主要使用流程

**你在外部ChatGPT讨论设计 → 确认方案并沉淀文档 → 你或获授权的AI代理指定负责人和处理范围 → 负责人读取并专业核对 → 获准后由主开发/DSH实现、测试和修复 → 你查看成果，只对必要事项作判断。**

这是制作人于2026-10-22确认的日常设计主线。直接在工作台聊天仍可用于澄清、技术安排和跟进，不要求每项普通工作先重新讨论设计。

| 阶段 | 谁处理 | 你或代理要说清什么 |
|---|---|---|
| 讨论与沉淀 | 你与外部ChatGPT | 确认了什么、哪些还待定；形成哪份设计文档 |
| 交接 | 你或获授权代理 | 文档路径/版本，交给谁，“先审查”还是“按阶段实施” |
| 专业接手 | 默认主策划；你可明确指定主开发 | 负责人核对原文档、项目与权威，普通疑问自行协作 |
| 开发与验证 | 主开发组织DSH | 已授权的工程和边界、要达成的效果；技术拆包/测试/修复交负责人 |
| 成果判断 | 负责人先专业复核，你或有明确验收委托的代理处理 | 看实际成果、验证与遗留问题；要求本人体验的事项由你完成 |

“请读一下、给意见”只做阅读评估；“按这个方案在本阶段完成”才表示在明确范围内实施。确认设计不自动授予正式仓库写入权限，阶段授权清楚后也不需要你批准每次普通技术修复。

让AI替你操作时，直接让它阅读[AI代理制作人操作说明](PRODUCER_PROXY_GUIDE.md)。它可在真实委托内发送、查询、跟进及按明确标准代理验收；不能虚构你的决定，或把代理动作说成人类本人已经体验。

下文“你”的日常操作也可由你的获授权代理代办；标明本人体验、本人决定或超出委托的事项除外。仅让AI代操作，不等于把所有产品选择和权限决定永久委托给它。

**当前实现边界：** 以上是已确认流程；一键文档交接尚未完整实现。现在可在负责人会话指定文档和范围；读取受限时按文档说明处理并明确实际内容来源。专用交接仍为手动扫描/通知，不要把它描述为自动读取原文件成功。第2节是首次打开/配置的操作步骤，不是替代外部设计入口。

## 1. Studio 是什么，你要做什么

Studio 是在本机运行的游戏研发协作工作台。你提出目标、判断重要产品取舍、体验和评审成果。两位 AI 负责人用简体中文自主推进授权范围内的专业工作：

| 对象 | 主要职责 | 什么时候找他 |
|---|---|---|
| 主策划 | 玩法、规则、数值、设计文档及设计一致性；必要时直接咨询主开发 | 讨论设计，判断规则，整理设计交接 |
| 主开发 | 技术方案、工作包拆分、依赖和串并行安排、DSH 委派、测试、修复和成果复核 | 实现功能，定位缺陷，评估技术可行性 |
| 制作人（你） | 目标、重要产品取舍、明确指定的人工验收、权限与重大风险决定 | 不需要替 AI 检查每条日志或批准每次技术修复 |
| DSH + DeepSeek | 由负责人委派的开发执行层，进行限定工作包内的文件操作与可用的测试 | 通常交由主开发安排，不是第三位长期负责人 |

你与主策划、主开发分别在固定的长期会话中交流。网页关闭不会清空会话，也不会停止后台任务。普通技术工作和设计自查默认自主完成；只有重要判断或你明确指定的成果才需要你验收。

**配置工程、获得写入授权、开始执行、验证通过是四件不同的事。** 选中工程路径并不意味着 DSH 能修改该仓库，连接成功也不意味着所有工具可用。

## 2. 第一次打开：先做这三步

### 第一步：打开并确认状态

访问 http://127.0.0.1:3178/ 。如果打不开，按[运行手册](RUNBOOK.md)启动后台；不必重复安装依赖。

进入「设置」，查看「运行与工作范围」：工程路径是否正确，后台是否已连接，认证是否可用。认证异常交给维护者处理，不要把账号令牌贴进会话。

本机在 2026-10-22 已完成一次初始化：工程根目录为 `<本地路径>`，两位负责人已创建，Unity 未配置。该记录是当日配置快照，后来是否变化以设置及维护者核对为准；本说明不要求重建会话。

若两位负责人确实都未绑定，展开「设置 → 专业诊断与恢复 → 执行连接」，点击「初始化两位负责人」。这会建立两个会话并写入角色规则，不会自动阅读整个项目或开始研发。已有正常绑定时不需要再初始化；不要使用「受控绑定 / 替换」作为日常初始化。

### 第二步：在会话中说明目标与边界

进入「会话 → 你 ↔ 主开发」。初次接手可复制以下内容，按你的实际目标调整后发送：

> 请先只读接手当前配置的工程，按根目录 AGENTS.md 和 README 指引阅读项目权威入口。用简明中文告诉我：当前已完成什么、尚未解决什么、你建议下一步做什么。区分文档历史与本机事实。暂不修改文件、不启动 DSH 或 Unity 测试、不自动进入下一工作包；需要补充信息时问我。

这是一个真实模型请求，会使用账户额度；**本指南中的示例没有替你执行**。如果你已经有清晰目标，可以直接说目标，不必每次重新接手。设计问题直接找主策划，不要求主策划转述所有技术需求。

通用文件工具已修复中文/空格路径读取；仍限允许类型的UTF-8小文本（64KiB）和配置工程范围。负责人遇到超限或其他读取失败应明确说明具体资料，不能假称整个项目已读，详见AI协议第3节。

发送前确认输入框上方「关联任务」：初次讨论选择「普通对话 · 不创建任务」。普通对话不会自动新建任务，但负责人可按你明确提出的研发目标使用工具登记任务。

### 第三步：形成一个边界清楚的工作目标

例如：

> 请分析当前人物详情页的一个明确问题，先给出原因、影响范围和最小修复建议。当前只授权分析，不改文件。分析可以由你专业自查完成；如涉及玩法变化，直接与主策划核对。给我结论、依据、未验证项和下一步建议。

准备执行时，再明确“允许在哪个目录改什么、不得改什么、需运行什么验证、什么情况需要我决定”。不能把“认可建议”自动理解为授予系统权限或正式工程写入权限。

## 3. 四个入口怎么配合

| 入口 | 主要回答 | 日常操作 |
|---|---|---|
| 工作台 | 当前目标、负责人进展、最近成果、风险、哪些事需要你决定 | 整理阶段目标；进入负责人聊天；打开成果；回答判断事项 |
| 会话 | 你说了什么、负责人如何回复、双方如何协作 | 选择负责人；发中文消息；关联任务；必要时查看完整历史 |
| 任务 | 一项具体工作交付了什么、验证到哪一步、下一步是什么 | 展开任务卡片和成果；查看进度；继续、修订或验收 |
| 设置 | 当前工程、连接与执行限制是否正确 | 查看状态、备份；维护者在专业诊断中处理恢复与绑定 |

首次进入默认工作台，此后记忆上次入口。聊天直达保留。任务登记表、任务详情和技术记录默认折叠，点标题或「手动登记任务」「阅读完整成果、验证与反馈」展开；字段没有显示通常应先展开，而不是重复点击提交。

首页「整理阶段目标」只保存目标与下一步，**不会派发任务、调用模型或启动原生 Goal**。首页可能仍有“尚未选择研发工程”的通用空状态文字，不能据这句话否定设置中的实际工程配置。

「研发进展」用于阅读业务变化；「标记看过」仅更新已读位置，不批准成果、不关闭风险。技术事件保留在折叠详情中。

## 4. 日常研发：文档接手后自主推进

推荐流程：

1. 设计工作先按上方主线形成确认文档，再由你或获授权代理交给负责人，指定审查或实施范围；普通技术目标也可直接说明目标与约束。
2. 负责人读取指定版本并核对项目资料，必要时直接向另一负责人提问，制定技术或设计方案。未读到原文档不能冒称完成接手。
3. 对有明确交付的工作，负责人登记任务、拆分工作包。普通专业任务自主推进，不要求你反复手工派发。
4. 具备授权和执行条件时，主开发委派 DSH。执行目录、阶段、预算、文件操作及验证均须与授权一致；执行结果自动回传原负责人，不需要你复制粘贴报告。
5. 主开发复核实际文件、测试、错误与副作用；主策划核对设计质量。负责人提交中文成果、证据、未完成项和下一步。
6. 普通专业工作按完成标准关闭；重要产品决定或指定人工验收才交给你。

**当前保留的独立目录 DSH 模式不会自动把配置工程复制进去，也不会自动将结果合并回游戏仓库。** 若目标是修改现有游戏代码，主开发必须先确认源码输入、实际修改位置、集成方式及授权；不能把独立目录中的文件当作仓库已改。Unity 连接与执行也需另行配置和验收。

## 5. 如果要自己登记任务

进入「任务」，展开「手动登记任务（通常直接在会话中安排即可）」：填写任务标题、目标与完成条件、指定负责人。

高级选项按需选择：

- **执行方式**：Codex 负责人直接处理，或交给 DSH 开发执行层。一般让主开发选择即可。
- **完成标准类型**：文字分析、设计自查，或真实实现与验证。选择真实实现后，后台要求真实执行验证记录；无法运行应标阻塞，不要改为分析来绕过。
- **验收方式**：「凭证据自主完成」用于普通专业工作；「制作人指定验收」用于你确实需要体验、审查或判断的交付。
- **Unity工程验证**：只有已手动打开、显式配置并获执行授权的工程才选用。不是勾上就自动启动编辑器。

表单提交仅登记任务及负责人，**不会立即执行**。展开任务卡片后按当前状态操作：

| 按钮 | 实际行为 | 不会发生 |
|---|---|---|
| 发送首次执行指令 | 给原负责人发一条与该任务关联的指令；忙碌时排队 | 不新建另一任务，不代表已经执行完成 |
| 继续已有任务 | 沿用同一任务和负责人上下文，补充下一步指令 | 不清除旧结果，不自动解决权限问题 |
| 重新执行已结束任务 | 在同一任务内新增重做请求，保留历史；可能重复工具副作用和消耗额度 | 不复制成新任务，不撤销之前操作 |
| 提交 DSH 执行 | 为 DSH 类型任务建立一个独立执行与 Session；选择文件工具或本次 Managed Shell | 不自动写正式仓库，不等于专业验收通过 |
| 进入负责人会话 | 切换到负责人并关联此任务 | 本身不发送消息 |

执行面板中阅读目标、负责人、当前状态和影响，填写明确指令，按要求勾选确认再提交。取消不会发出本次未提交请求；提交中不要重复点击。提交成功先表示已记录，继续看实际消息和任务状态。已有待处理或未知指令时后台会阻止重复派发。

DSH 只有两个并发槽位；满额时新请求会拒绝，不是无限队列。独立任务可并行，同一 Unity 工程不可并发写入或冲突测试。不要给同一目标同时点击 Codex 继续和 DSH 执行。

Studio默认不再附加4096 token输出上限，但模型自身仍有上限，不能保证永不截断。运行中的工作由后台定时检查，必要时请原负责人核对；没有变化不会不断唤醒模型。定时检查不是自动重做或验收。完整任务可以内部拆成独立工作包并行，但不会因此让你逐包审批。

## 6. 怎样看懂状态和成果

### 看DSH是否还有新进展

进入「任务」，展开对应任务，在每条「DSH 执行记录」标题下查看「最近执行活动」。这里显示具体日期时间（你的浏览器本机时区）和“多久前”；收到新的原生执行事件后自动更新，相对时间每10秒更新。它不需要打开原始日志，也不触发模型调用。

时间取自原生执行事件，不使用任务状态修改、页面刷新或传输确认的时间；恢复旧事件不会显示为新工作。没有可靠时间就显示“尚无带时间的原生执行事件”。时间变久只表示尚无新事件，可能在等待模型或工具，不等于已失败；“执行中”也不等于成果通过。查看具体步骤仍可展开「执行身份、工作目录与原始证据」并点击「读取原始执行事件」，该面板是点击时的快照。

### 三种状态不要混为一谈

| 对象 | 例子 | 怎么理解 |
|---|---|---|
| 消息 | 已记录、派发中、已接收、执行中、未知 | 表示指令投递/处理进度；不是成果验收 |
| 任务 | 待处理、执行中、阻塞、待验收、已完成 | 表示工作登记状态；还需核对交付与验证 |
| DSH 执行/阶段 | 准备、运行、阶段结束、失败、结果待核对 | 表示某次执行；模型结束不等于目标完成 |

「未知/待核对」表示没有足够证据判定投递或执行结果，不代表“没有执行”。「阻塞」应说明条件缺失及负责人下一步；制作人点击通过不能替代缺失测试。

### 每次成果看这六件事

展开「阅读完整成果、验证与反馈」：

1. 目标与边界：解决的是不是原问题？
2. 实际交付：改了什么，文档或文件在哪里？
3. 已完成验证：运行了什么，结果怎样，针对哪个版本？
4. 未完成验证与已知问题：还有什么风险，为什么没测？
5. 你需要判断什么：没有产品判断事项就不必人工批准。
6. 下一步：谁负责继续，是否有依赖？

验证标签含义：真实执行、模拟测试、分析/专业自查、来源未核实。**“真实执行”是提交者声明并附证据，不是系统独立复验所有内容的保证。** 主开发须复核日志、退出码、实际差异和测试计数。

文字成果直接阅读；项目文档通过「查看项目文档」只读打开允许的小文本。此入口不能打开任意文件、Excel、大型资产或运行程序。「原型入口尚未安全核验」意味着当前只保留引用，不能当成一键可玩成果；让负责人提供实际可用的体验方法。

## 7. 需要你决定时怎么处理

### 产品决定

首页「需要制作人关注」中的决定应说明问题、事实和备选方案。填写你的选择与范围后提交，回答会回原负责人。缺材料时先追问，不必替负责人猜结论。答复仅授权你明确说出的范围。

### 指定人工验收

| 操作 | 你填写什么 | 提交后的真实影响 |
|---|---|---|
| 继续讨论 | 一个具体疑问，例如“这个规则与原设计是否冲突？” | 发给原负责人，任务保持待验收；等回复后再决定 |
| 要求修改 | 哪项成果需改变、期望效果、边界 | 保留原交付与反馈，向原负责人发修订请求；任务先待处理，进入修订流程 |
| 通过验收 | 本次认可的成果和通过范围 | 记录本交付版本的制作人通过，不发送执行指令，不扩大权限 |

通过前应能看到可读成果和判断材料；按钮不可用时先看原因，可能是材料不足、版本变化或仍有未结束指令。任务变化后关闭面板重新核对；不要用专业维护的状态更正代替验收。

普通工作不会因通知你进展而自动要求批准。「待验收」也不表示所有测试已独立复验。若仍欠目标要求的真实验证，要求原负责人补齐或标明阻塞。

## 8. 聊天、协作和完整历史

「你 ↔ 主策划」「你 ↔ 主开发」是日常入口；「主策划 ↔ 主开发」只是两位负责人的消息筛选，没有第三个会话或执行者。

正文用中文阅读。工具、命令、ID、JSON 默认折叠；要追溯时展开「消息详情」「最近工具与执行记录」。搜索只是筛选，不是完整原生会话读取。

需要核对实际 Thread 时点击「查看原生会话历史 → 读取原生历史」，有更多时继续加载。若提示读取受限，只能据实际读到的记录判断，不能把空列表当作不存在。

忙碌时普通新消息进入待派发队列，不会立即改变当前执行。确需改变正在运行的 Codex Turn，可在原生历史栏使用「调整执行方向」；「中断执行」只请求中断，不回滚已发生的文件操作，也不等于停止另一个 DSH Session。DSH 需在任务的执行卡使用「停止本次执行」，并等待权限回收结果。

## 9. 常见问题：按这个顺序处理

| 现象 | 先做什么 | 避免什么 |
|---|---|---|
| 按钮/输入框找不到 | 展开登记表或对应任务卡片；检查当前页面/负责人 | 不取消折叠、不连续提交 |
| 发送后没有回答 | 看消息是排队、执行中、失败还是未知；再看原会话 | 不把“已记录”当回答，不连续重复发送 |
| 网页断线或刷新 | 重新打开原地址，核对最新任务和消息 | 不重新建负责人或重做任务 |
| 提交超时、结果不明 | 保留当前浏览器操作记录；若出现“使用相同标识核对重试”则只核对原请求 | 不改写未知请求再发、不清除存储来“解决” |
| 负责人不可用 | 设置查看认证/连接；必要时请维护者核对原绑定 | 不随意替换 Thread |
| 重新连接后任务继续 | 正常：恢复操作可能派发已记录待发消息，先检查队列 | 不把刷新认证视为绝对只读 |
| DSH 失败/max-tokens | 交原主开发看已有阶段、输出及用量，决定有界续接或缩小工作包 | 不无限重试，不盲目增加 Token |
| 临时权限回收待核对 | 停止新的 Shell 工作，请维护者处理原执行 | 不关沙箱、改 Full Access 或手工删权限记录 |
| Unity 未连接/工程不符 | 手动确认编辑器工程和版本，交维护者检查端口、令牌、编译/许可证 | 不反复启动编辑器，不连接另一个工程试写 |
| 测试超时 | 由主开发核对编辑器日志、原测试状态和结果；未知状态保留工程锁 | 不立即重跑同一测试、不靠清锁绕过 |

停止工作：网页可直接关闭；需要关后台使用正常关闭脚本，详见运行手册。关后台也可能将进行中的执行变为待核对；它不是回滚。重要阶段请备份。

## 10. 你是否已经学会上手

你应能做到：确认当前工程和限制；选择合适负责人；发送一项范围明确的请求；找到任务与回复；读懂交付和未测边界；区分继续讨论、修订和通过；出错时先核对原记录。如果其中某步在实际界面不可用，记录入口、可见提示和期望行为交主开发处理，不靠改状态假装成功。

本指南依据现行源码与隔离回归编写；示例未在你的活动数据库生成任务。旧实验报告是历史证据，不作为今天工程已接通、测试已通过或权限已授予的证明。

## 11. 任务树：总目标、工作包与详情

“任务”页按明确的父子关系组织工作。顶层任务对应研发目标，子任务对应该目标内登记的工作包；同一父任务下是同级工作。树的上下级是工作范围关系，不改变主策划和主开发的平级协作、权限或验收职责，也不自动代表执行先后依赖。

- 点击“展开子任务（数量）”只显示下级；点击“查看详情”只打开该任务的进展、交付、指令和证据。点击标题或卡片空白不展开详情。子任务也可以继续有下级。
- 父任务显示直属子任务数、全部下级数、本任务及下级活跃执行数、最近变化。任务树汇总下级执行，不因为下级结束就自动完成父任务。
- 创建、首次执行、最新记录更新、最近DSH活动分别显示；首次执行缺证时不使用创建时间代替。最近变化包含归属调整等账本变化，不等同实际写代码；DSH原生活动另有时间。
- 新建任务时可选“上级任务”。已有任务进入详情后可用“调整任务归属”，说明依据；可改为顶层，不启动执行，不改变负责人、完成状态、验收与权限。系统阻止指向自身、下级或不存在的父任务，并防止用过时页面覆盖新变化。
- 搜索命中子任务时保留上级路径；明确收起的分支可用展开按钮查看。加载更多仍适用，某些下级不在当前筛选或加载范围时会提示。
- 原生负责人创建工作包时，可显式提供parentTaskId；旧工具调用没有该字段时，只有当前原生Turn的可信来信唯一关联一个任务，才沿该上下文建立父子关系。无法确认的保持顶层，不按标题猜测。
- 旧任务整理只补经核实的关联，不删除旧失败、不批量改状态、不自动撤销验收。2026-10-24的R3-B整理将总目标下三张既有工作单列为同级子任务；这不表示三项正在同时执行。

## 12. 像聊天记录一样阅读DSH执行历史

在任务详情中点击“展开执行记录”。区域首次只呈现最近5条，自动定位到最下方最新记录；旧记录在上，向上滚动分批加载，也可点击“加载更早记录”。这是工作台执行记录的阅读区，不是DSH原始聊天窗口。

记录区有独立滚动条；上方的“收起执行记录”和“回到最新记录”不会随区域内部滚动消失，不需要返回整张任务卡顶部。查看旧记录时收到新记录，只提示“有新记录，查看最新”，不打断阅读；停留在底部时跟随新记录。重新展开回到最近5条。

收起状态仍显示总条数和最近一次登记的执行状态。执行详情、停止执行确认、阶段进度和原始工具证据均保留；收起不会停止执行，展开不会重新派发任务。开始和记录更新时间显示北京时间；最近执行活动仍以原生事件时间为准。

## 13. 制作人事项、技术协助与通知

“需要制作人关注”用于产品取舍、指定验收、新权限或重大风险。技术排查、执行恢复、日志核对由负责人在既有授权内自主处理；缺少宿主能力时进入默认折叠的“技术协助与维护记录”，保留原始求助与历史，不要求你盲目批准。没有归属字段的旧请求放入待核对区，由维护端依据原始证据分类；不按标题或关键词猜测、不擅自关闭。

右上角“通知”显示未读数。新决定、原生答复请求、材料齐备的指定验收、负责人最终回复和新交付报告可产生提醒；普通工具日志、过程说明和已归类技术协助不生成制作人红点。点击查看会进入相应会话、任务或制作人事项；标记已读不批准成果、不回答问题、不改变任务状态。已读标记只存于当前浏览器，按工作台数据批次隔离，不跨浏览器同步。

默认有红点和页面浮动提醒。在通知面板可手动开启声音和系统通知；声音需本页用户交互解锁，系统通知需浏览器允许。未获允许时仍保留页面提醒；可随时关闭。网页关闭后不保证提醒，不是后台推送服务。首次打开不把已有聊天/报告历史批量弹窗，旧的未解决决定仍可显示未读；同一条记录刷新不会反复提醒。

主开发应使用既有工具主动登记真正需要制作人的问题，用中文写清理由、选项、建议和影响。新增决定可指定audience=producer或technical；旧长期Thread工具schema不含该字段时，技术协助明确在question开头标记【技术协助】，保持旧接口兼容。归类不授予新权限，也不代表已处理。

技术协助有一次有界负责人核查；同一任务不由该机制循环唤醒。Unity因播放占用被明确拒绝、测试尚未投递时，后台可每分钟只读核对原配置工程与TestRunner。只有真实空闲、无新执行/未知请求/工程锁、原负责人空闲等条件满足，才向原负责人发送一次恢复核查请求。每任务最多一次此类自动提醒；不自动重跑测试、不结束Play、不清锁、不恢复存档、不改完成状态，也不突破权限。原结果未知、存档或权限风险仍须维护端核实，不能把此机制当成所有技术故障都已自动修复。
